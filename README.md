# Animle

A daily wildlife game in three rounds: name the animal, estimate its wild population, paint its range on the map.

## Commands

| Command | What it does |
| --- | --- |
| `npm run dev` | Start the game locally at http://localhost:5183 with live reload |
| `npm run build` | Build the production site into `dist/` |
| `npm run preview` | Serve the built site at http://localhost:4183 |
| `npm test` | Unit tests and content validation |
| `npm run e2e` | Full playthroughs in a real browser at desktop and phone sizes (run `npm run build` first if a preview server is already running) |
| `npm run photos` | Download species photos from Wikimedia Commons (cached in `.cache/`), check licences, write crops and credits |
| `npm run sheets` | Write review sheets of every photo to `.cache/`; add `-- 0` for the first close-up |
| `npm run check-ranges` | Compare each range with wild sighting records from GBIF and flag gaps |
| `npm run review` | Show which species a second person has signed off, and the checklist |
| `npm run review-sheet` | Write `docs/SPECIES-REVIEW.md`: every species with its figures, sources and photo credit, for the reviewer |
| `npm run check-batch <file>` | Validate one species batch file on its own |
| `npm run find-photo "<search>"` | List Wikimedia Commons photos with a usable licence, to replace an unsuitable lead image |
| `npm run schedule` | Rebuild the future part of the daily schedule; never changes days already played or due in the next 10 days |
| `npm run preview-focus <id> [x y]` | Preview a photo's close-ups for a focus point, in `.cache/preview/` |
| `npm run prune-guesses` | Remove animals from the guess list that have become answer species |
| `npm run check-artifact` | After `build:artifact`, check the artifact build's photos in a real browser |
| `npm run screenshots` | Play a game against the preview server and save a screenshot of every screen to `.cache/shots/` |
| `npm run icons` | Regenerate app icons and the social preview image |
| `npm run build:artifact` | Build the copy that is published as a Claude artifact, into `dist-artifact/` |

## How the game works

There are 130 species: 125 take turns as the daily, and 5 easy ones (giant panda, koala, polar bear, African bush elephant, emperor penguin) are practice animals. Practice animals are listed in `PRACTICE_IDS` in `src/data/speciesExtra.js`; they are never a daily and never join the zoo.

- **Round 1, five guesses.** Each miss zooms the photo out, unlocks a clue and says how closely the guess is related (same class, order, family or genus). Solving scores 500, 425, 350, 275 or 200. Not solving still scores up to 175 for the closest relative guessed.
- **Round 2.** Any guess inside the published population range scores 1000. Outside it the score falls with the order-of-magnitude distance.
- **Round 3.** The world is covered in about 2,600 equal-area hexagonal cells. The player paints cells; cells beside the true range count for half. It works by touch, mouse and keyboard.
- **Zoo.** Scoring 1,250 or more on a daily adds its animal, with a bronze, silver or gold badge for the best score. The zoo is laid out by region. Animals that were played but not earned, and dailies that were skipped, are "missed"; from a 3-day streak the player can retake one missed animal a day. A first retake needs 1,500, and each further retake of the same animal needs 250 more, up to 2,100. Practice and past dailies can raise a badge but never add an animal. A backup code moves progress between devices.
- **Past dailies.** Any earlier daily can be played by number without changing the streak or daily stats.

## Where things live

- `src/data/species.js`: the first 24 species, and the code that merges in the rest.
- `src/data/speciesExtra.js`: extra fields for those first 24 (taxonomy, size, last clue, population range, zoo region), and the review sign-off list.
- `src/data/batches/`: the other 106 species, one file per zoo region, with every field in one place. `README.md` there shows the format.
- `docs/NEXT-STEPS.md`: what is left before launch and who does it. `docs/SPECIES-REVIEW.md`: the review sheet.
- `src/data/taxonomy.js`: every animal a player can guess (about 750) with its class, order, family and genus.
- `src/data/photos.json` and `public/p/`: generated by `npm run photos`. File names are hashes so they do not reveal the animal.
- `scripts/photo-focus.json`: where each photo's close-up centres, and how tall photos are framed.
- `src/engine/`: scoring, the map grid, guess matching, the daily schedule, streaks and saved data. No interface code, fully unit-tested.
- `src/map.js`: the paintable map for round 3.
- `src/main.js`: the interface.

## Before going live

- Puzzle No. 1 is 16 November 2026 (`LAUNCH_DATE` in `src/engine/daily.js`). Do not change it: every puzzle number counts from it.
- Read the Privacy and Terms dialogs in `index.html`. They are plain-language drafts and have not had legal review.
- Pushing to `main` on GitHub runs the tests and publishes `dist/` to GitHub Pages (`.github/workflows/deploy.yml`). In the repository, set Settings > Pages > Source to "GitHub Actions" once.

## Adding a species

1. Add an entry to the right file in `src/data/batches/`, following `src/data/batches/README.md`. Run `npm run check-batch src/data/batches/<file>.js`.
2. Run `npm run check-ranges -- --batch src/data/batches/<file>.js <id>` and widen the range if busy sighting cells fall outside it.
3. Run `npm run photos <id>`, then `npm run sheets` and look at the photo in `.cache/`. If the article's lead image is a map, a drawing or has a licence the script rejects, pick another with `npm run find-photo` and add it to `OVERRIDES` in `scripts/fetch-photos.mjs`. Set a focus point in `scripts/photo-focus.json` if the close-up gives too much or too little away, and run `npm run photos <id>` again.
4. Run `npm run prune-guesses` so the animal is not also on the guess list.
5. Run `npm test`. The content tests fail if anything is missing, a clue names the animal, or a photo licence is not allowed.

6. Run `npm run schedule` so the new animal gets a day (see below).

## The daily schedule

`src/data/schedule.js` is a fixed list: one species id per day, starting on launch day. The game only reads that list, so editing a species' clues, numbers, range or photo never changes which animal a date shows, and neither does adding a species.

- `npm run schedule` keeps every day up to 10 days from now exactly as it is and rebuilds the days after that from the species that exist now. Animals that have never had a day are placed first. No animal returns within 30 days.
- Run it after adding species, and again before the list runs out (the command prints the last date). Past the end, the list repeats from the top.
- Do not delete a species that has already had a day: past dailies and players' zoos refer to it. Fix it instead.
- When a day has gone live, add its animal to `PUBLISHED` in `tests/daily.test.js`. That test fails if a later change would alter history.

## Second-person review

`npm run review` lists the checklist and who has signed off each species. Record a sign-off in `REVIEWED` in `src/data/speciesExtra.js`. Once every scheduled species is signed off, set `REQUIRE_REVIEW` to `true` so that only reviewed species can become dailies.
